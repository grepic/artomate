# Database Migrations with Alembic

This directory contains database migrations managed by [Alembic](https://alembic.sqlalchemy.org/).

## Quick Start

### Run migrations (upgrade to latest)
```bash
alembic upgrade head
```

### Create a new migration after changing models
```bash
# After editing artomate/db/models.py
alembic revision --autogenerate -m "Add new column to jobs table"
```

### View migration history
```bash
alembic history
```

### View current version
```bash
alembic current
```

### Rollback to previous version
```bash
alembic downgrade -1
```

### Rollback to specific version
```bash
alembic downgrade <revision_id>
```

## Common Workflows

### 1. Adding a new column to existing table

```python
# 1. Edit artomate/db/models.py
class Job(Base):
    # ... existing columns ...
    new_column: Mapped[str] = mapped_column(String, nullable=True)
```

```bash
# 2. Create migration
alembic revision --autogenerate -m "Add new_column to jobs"

# 3. Review generated migration in alembic/versions/

# 4. Apply migration
alembic upgrade head
```

### 2. Creating a new table

```python
# 1. Add new model in artomate/db/models.py
class NewTable(Base):
    __tablename__ = "new_table"
    id: Mapped[int] = mapped_column(primary_key=True)
    # ... columns ...
```

```bash
# 2. Create migration
alembic revision --autogenerate -m "Create new_table"

# 3. Apply migration
alembic upgrade head
```

### 3. Renaming a column

```python
# Manual migration required (autogenerate can't detect renames)

# Create migration:
alembic revision -m "Rename column_old to column_new"

# Edit the generated file:
def upgrade():
    op.alter_column('table_name', 'column_old', new_column_name='column_new')

def downgrade():
    op.alter_column('table_name', 'column_new', new_column_name='column_old')
```

## Migration Files

Migration files are stored in `alembic/versions/` with format:
```
{revision_id}_{description}.py
```

Each migration has two functions:
- `upgrade()` - Apply the migration
- `downgrade()` - Rollback the migration

## Configuration

- `alembic.ini` - Alembic configuration
- `alembic/env.py` - Migration environment setup
  - Automatically loads database URL from `artomate.core.config`
  - Imports models from `artomate.db.models`

## Best Practices

1. **Always review autogenerated migrations** before applying
2. **Test migrations on development database** before production
3. **Create descriptive migration messages**
4. **Never edit applied migrations** - create a new one instead
5. **Backup database** before running migrations in production

## Troubleshooting

### "Target database is not up to date"
```bash
# Check current version
alembic current

# Upgrade to latest
alembic upgrade head
```

### "Can't locate revision identified by 'xyz'"
```bash
# Check history
alembic history

# If migration file is missing, restore it from git
```

### "FAILED: Multiple head revisions are present"
```bash
# Merge heads
alembic merge heads -m "Merge migrations"
```

## Development vs Production

### Development
```bash
# Drop all tables and recreate with latest schema
python -m artomate.cli.main reset-db
python -m artomate.cli.main init-db

# Or use migrations
alembic downgrade base
alembic upgrade head
```

### Production
```bash
# ALWAYS use migrations in production
alembic upgrade head

# NEVER use reset-db in production!
```

## Integration with CLI

You can also manage migrations through the CLI:

```bash
# Initialize database (creates tables without migrations)
python -m artomate.cli.main init-db

# For production, prefer Alembic:
alembic upgrade head
```
